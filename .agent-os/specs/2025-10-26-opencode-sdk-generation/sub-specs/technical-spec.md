# Technical Specification

This is the technical specification for the spec detailed in @.agent-os/specs/2025-10-26-opencode-sdk-generation/spec.md

> Created: 2025-10-26
> Version: 1.0.0

## Technical Requirements

### Saloon SDK Generator Configuration

- Use `crescat-io/saloon-sdk-generator` version `^1.3.1` (already in composer.json)
- Source OpenAPI spec: `packages/opencode-sdk/swagger/2025-10-26.json`
- Generate into namespace: `ArtisanBuild\OpencodeSdk\OpenCode`
- Output directory: `packages/opencode-sdk/src/OpenCode/`
- Include all endpoints from the OpenAPI spec

### Generated SDK Structure

The Saloon SDK generator will create:
- **Connector class**: `OpenCodeConnector` - main entry point, handles base URL and authentication
- **Resource classes**: Organized by API sections (e.g., `SessionResource`, `ConfigResource`, `FileResource`)
- **Request classes**: Individual request classes for each endpoint operation
- **DTO classes**: Data transfer objects for request/response payloads

### Configuration File Structure

**File**: `packages/opencode-sdk/config/opencode-sdk.php`

```php
return [
    // Base URL for the OpenCode API
    'base_url' => env('OPENCODE_BASE_URL', 'http://localhost:3333'),

    // Request timeout in seconds
    'timeout' => env('OPENCODE_TIMEOUT', 30),

    // Optional authentication (if needed in future)
    'auth' => [
        'type' => env('OPENCODE_AUTH_TYPE', null), // 'bearer', 'api_key', null
        'token' => env('OPENCODE_AUTH_TOKEN', null),
    ],

    // Retry configuration
    'retry' => [
        'times' => env('OPENCODE_RETRY_TIMES', 3),
        'sleep' => env('OPENCODE_RETRY_SLEEP', 100), // milliseconds
    ],
];
```

### Service Provider Integration

Update `OpencodeSdkServiceProvider` to:
1. Register the config file (already done)
2. Bind the `OpenCodeConnector` to the container as a singleton
3. Configure the connector with values from the config file
4. Apply base URL, timeout, and authentication from config

Example binding:
```php
$this->app->singleton(OpenCodeConnector::class, function ($app) {
    $config = $app['config']['opencode-sdk'];

    $connector = new OpenCodeConnector();
    $connector->setBaseUrl($config['base_url']);

    // Apply timeout and other configurations

    return $connector;
});
```

## Approach

**Selected Approach: Use Saloon SDK Generator CLI**

Run the Saloon SDK generator command directly in the package directory:

```bash
cd packages/opencode-sdk
vendor/bin/saloon-sdk-generator generate \
    --input=swagger/2025-10-26.json \
    --output=src/OpenCode \
    --namespace="ArtisanBuild\\OpencodeSdk\\OpenCode" \
    --connector-name=OpenCodeConnector
```

**Rationale:**
- Saloon SDK generator is designed specifically for this use case
- Handles all the boilerplate of creating connector, resources, requests, and DTOs
- Generates type-safe code with PHPDoc annotations
- Automatically handles request/response serialization
- Supports all OpenAPI spec features (paths, schemas, parameters, etc.)

**Alternative Considered: Manual SDK Creation**
- Pros: Full control over structure and naming
- Cons: Extremely time-consuming, error-prone, harder to update when API changes
- **Not selected** because Saloon generator provides excellent code quality with zero manual effort

## External Dependencies

No new external dependencies required. The package already has:

- **saloonphp/saloon** (^3.0) - The Saloon HTTP client library
- **crescat-io/saloon-sdk-generator** (^1.3.1) - SDK generation tool

## PSR-4 Autoloading

The `composer.json` already has the correct PSR-4 autoloading:

```json
"autoload": {
    "psr-4": {
        "ArtisanBuild\\OpencodeSdk\\": "src/"
    }
}
```

This means `src/OpenCode/OpenCodeConnector.php` will be autoloaded as `ArtisanBuild\OpencodeSdk\OpenCode\OpenCodeConnector`.

## Configuration Publishing

The service provider already has publishing configured:

```php
$this->publishes([
    __DIR__.'/../../config/opencode-sdk.php' => config_path('opencode-sdk.php'),
], 'opencode-sdk');
```

Users can publish with: `php artisan vendor:publish --tag=opencode-sdk`

## Error Handling

Saloon provides built-in exception handling:
- `RequestException` for failed requests
- Automatic status code checking
- Support for retry logic with exponential backoff

We'll leverage Saloon's built-in error handling rather than implementing custom exception classes.

## Type Safety

The generated SDK will include:
- PHPDoc annotations for all methods
- Strongly-typed DTOs for request/response data
- IDE autocomplete support
- PHPStan level 5 compatibility

## Testing Strategy

Tests will verify:
1. Configuration is loaded correctly
2. Connector is bound to the container properly
3. Generated SDK classes exist and are autoloadable
4. Basic request creation works (using mocked responses)
